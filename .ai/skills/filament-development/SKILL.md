# Filament Development

- Filament 5 (`filament/filament`), panel id `admin`, provider `app/Providers/Filament/AdminPanelProvider.php`, path `/admin`. Use `search-docs` (packages: filament) before relying on version-specific API; do not assume Filament 3/4 syntax.
- Generate with Artisan through Sail: `vendor/bin/sail artisan make:filament-resource Model --generate`, `make:filament-page`, `make:filament-widget`. Do not hand-write what a generator produces; edit the output.
- Keep resources thin: put business logic in actions/services/models, not in form or table closures.
- **Access:** outside `local`, users reach the panel only if `App\Models\User` implements `Filament\Models\Contracts\FilamentUser` with `canAccessPanel()`. Never loosen it to `return true` for convenience.
- **Authorization:** back every resource with a Laravel policy; Filament picks it up automatically. Do not add `->registration()` to the admin panel unless asked.
- **Queries:** eager-load relations shown in table columns (`->modifyQueryUsing(fn ($q) => $q->with(...))` or `getEloquentQuery()`) to avoid N+1.
- **Assets:** published assets under `public/{css,js,fonts}/filament` are gitignored and regenerated by `filament:upgrade` (composer `post-autoload-dump`) on deploy. Do not commit them.
- **Tests:** use Pest with Livewire testing helpers (`livewire(ListUsers::class)->assertCanSeeTableRecords(...)`), authenticated as a user who can access the panel.
